# dsh-anti-ai-fiction

反 AI 味质检排雷 + 强制拦截。查**内容层面**的 AI 味，命中重灾区就**打回重写**，不做润色。

## 解决什么问题

**AI 味 = 没有活人味。**

不是「辞藻不好」「句式太平」，是**这句话只有模型会写**。真人写的东西有具体的名字、有毛边、有让人难受的地方；模型写的东西处处正确、处处圆满、处处不痛不痒。

这个插件把那件事拆成**能查的判据**：40 条雷区，每条落成一句机器能查的话。查出来的每一条都带**原文证据**和**定位**（哪一句、第几段）—— 不是「感觉这里有点 AI」，是「这里，原文第三段，『残阳如血』」。

## 四维 40 条

| 维度 | 查什么 | 例子 |
|---|---|---|
| **名字** | 人名、称号、组织名、功法名、宠物名的套路化 | 「林凡」「灭世魔尊」「终极神剑诀」 |
| **事物** | 道具、法宝、系统面板、消耗品的说明书式描写 | 「叮！击杀低级丧尸，获得 10 点经验值」 |
| **对话** | NPC 式念白：自我剖析、设定解说、缺潜台词 | 「你好，我叫林风，今年十八岁，是个孤儿……我的梦想是成为一个伟大的修仙者。」 |
| **景色** | 脱离心境的写景：套话开场、全景相机、机械过渡 | 「清晨，阳光明媚，微风拂过树叶，鸟儿在枝头欢唱」 |

完整清单用 `deai_rules` 工具看。

## 可复核：每条命中都带证据

这是本插件跟「让模型自己判断一下有没有 AI 味」的根本区别。

参考的审计报告模板是三段式（🔍 词句扫描与拦截 / 🔪 强制手术 / 🏆 去 AI 味升级指令），但那个模板里全是**示例**，没有真证据 —— 审的人无法判断模型是不是在编。

本插件的每条命中必须给：

```
🔴 打回重写｜万能的「阳光明媚」开场
- 雷区 id：scenery.sunny-opening
- 定位：第 2 段
- 原文证据：> 清晨，阳光明媚，微风拂过树叶，鸟儿在枝头欢唱。
- 为什么这是 AI 味：毫无意义，极其水字数
- 判据：出现「阳光明媚/风和日丽/鸟语花香/万里无云」等天气套语，且无人物生理反应介入
- 放行条件：该句后面紧跟人物的具体感受
```

**指不出位置的命中会降级标注；指不出位置的 block 级命中直接导致打回** —— 无法定位就没法定向修改，模型改的时候会瞎改整段，风险比留着还大。

活人味示范也是**人工审过的**，不是模型现编：每条雷区配了一组 ❌AI味 / ✅活人写法 的验收用例（`lib/spec.js` 的 `CASES`），示范直接取自 good 侧。拿模型自己现编的示范去改它自己写的句子，等于没查。

## 打回机制怎么生效

三条路径都收口到 `lib/spec.js` 的 `judgeReject()` —— 判定逻辑只有一处实现，工具层、界面层、验证脚本共用。

**阈值数的是「不同的 block 级 specId 的个数」，不是命中处数。**

这是最容易搞错、也最影响实际行为的一处：

- ❌ 读法 A（命中 3 处就打回）：一段里把「残阳如血」写三遍就触发 —— 但那是**同一种病**写了三遍，不该拦；而且改掉其中两处就等于改好了。
- ✅ 读法 B（3 条**不同的** block 级雷区）：这才对应「重灾区」的说法 —— 病得五花八门，说明这稿子从根上塌了，局部补丁救不了。

举例：同一段里「残阳如血」出现 5 次 +「阳光明媚」1 次 → 只有 **2 条**不同雷区 → **不拦**。这是同一个写景习惯的两面，集中改一处写景就能解决。

打回之后**不做润色**：

| 工具 | 命中不同雷区数 ≥ 3 时的行为 |
|---|---|
| `deai_audit` | 报告总判写「**拒绝润色，要求打回重写**」，列出命中的重灾区及病理 |
| `deai_polish`（strict=true，默认） | 不渲染改写提示词，直接返回打回裁决 + 逐条病理 + 每条雷区的活人味替换示范 |
| `deai_guard` | 返回 `ok: false`，逐条列出原因，并附上强制指令 |

## 四个工具

```
deai_audit(text, projectDir?, dims?, specs?)   → 查：结构化审计报告（命中/证据/定位/病理/修复方向）
deai_polish(text, projectDir?, dims?, specs?, strict?, keep?, wordMin?) → 改：改写提示词，或打回裁决
deai_guard(text, limit?, dims?, specs?, dim?)  → 拦：写作前置门禁 + 可粘贴的强制指令
deai_rules()                                    → 40 条雷区 + 阈值 + 放行条件清单
```

- `dims`：`name` / `object` / `dialogue` / `scenery`，逗号分隔。
- `specs`：雷区 id，逗号分隔（如 `scenery.blood-sunset`）。
- `strict`：`deai_polish` 默认 `true`，即命中达阈值就拒绝润色。设 `false` 可强制走润色路径（此时提示词里仍会点名所有重灾区）。

### `deai_guard` 的门禁项

写作时的前置门禁，查四件事：

1. **重灾区命中**（block 级）
2. **工程词泄漏** ——「本章」「伏笔」「爽点」「信息差」这类给作者看的词跑进正文
3. **截断** —— 结尾没收尾、中文引号不成对、英文双引号数为奇数
4. **占位符残留** —— `{xxx}` / `TODO` / `FIXME` / `XXX` / `待补`

另加可选的字数下限。任一命中即返回 `ok: false`。

## 强制指令

`lib/prompt.js` 渲染三样东西：

- `renderForcedDirective()` —— **写作时必须带上的强制指令**。六条硬条款：禁止说明书式设定讲解 / 禁止套话 / 对话禁止长篇大论自我剖析（必须带口癖和潜台词）/ 写物品必须写出质感 / 写景色必须与人物心理形成投射 / 名字与身世要落地。**结尾明写「做不到就打回重写」** —— 没有这一段，前面所有条款都只是建议。
- `renderChecklist()` —— 章节级自查清单，写完逐条打勾用的短清单。
- `renderRewritePrompt()` —— 改写指令模板，两条关键约束：**只改列出的点**（模型最常见的事故是顺手重写全篇，把原本对的地方也改坏）；**不许把活人味改死**（去 AI 味最大的失败模式不是没改，是改过头 —— 把句子统一改成短句、把「铁锈、霉味」抽象成「岁月的气息」）。

禁用词清单**全部从 `lib/spec.js` 的词表取**，不硬编码第二份。检测器查的是 `spec.js` 里的词，指令里若另抄一份，两边一漂移就会出现「指令禁的东西检测器不管」—— 模型白改，检测器还报。

## 与 `dsh-writing-slots` 的 `deai_polish` 的分工

两个插件都叫 `deai_polish`，查的**不是同一层**：

| | `dsh-writing-slots` 的 `deai_polish` | 本插件的 `deai_polish` |
|---|---|---|
| 查什么 | **文风句式**：段首连续人称代词、明喻引导词（仿佛/似乎/宛如）、抽象情绪句式、对话标签 | **内容层面**：名字、事物、对话、景色 |
| 判据来源 | Style Anchor 产出的 `forbidden_list`（作者自己的样本里 0 次出现的句式） | 40 条固定雷区表（`lib/spec.js`），每条带放行条件 |
| 典型命中 | 「一种……的感觉」「莫名的……」 | 「林凡」「终极神剑诀」「叮！宿主击杀……」「阳光明媚」 |
| 上下文 | 需要项目（读 style-guide.md） | 不需要项目，单段文本即可 |

一句话：**writing-slots 查「这句话像不像我写的」，本插件查「这个故事像不像 AI 编的」。**

两者可以串联：先用本插件查内容层的硬伤（打回重写），再用 writing-slots 查文风层的句子（润色）。

## 设计要点

### 不自己调模型

和 `dsh-writing-slots` 一致：插件负责把判据算完、把提示词渲染好，模型只负责写和改。这样「有没有做到」是可验证的 —— 数字能验算，例句能定位，模型说「已润色」不算数。

### 零依赖

纯 Node 内置，无 `dependencies`。`peerDependencies` 只有 `@deepseek-ai/cordis`（宿主提供）。

### 错误一律收口

工具永远返回 `{ ok, message }`，不把异常抛给调用方。检测引擎（`lib/detect.js`）未交付时用**动态 import** 加载 —— 静态 import 缺失会导致整个插件加载失败、连带整个 profile 起不来；动态 import 失败只影响「查」这件事，插件照样注册工具、照样返回 40 条规则、照样给出强制指令。

### 人工门禁

插件不替人做决定。`deai_polish` 的输出里明写人工门禁在哪；改写指令要求模型**如实写出自查没过的项** —— 假过的稿子会被当成真的写下去。

## HTTP 接口

```
GET  /api/dsh-anti-ai-fiction/spec   → 40 条雷区 JSON（含判据、放行条件、good 示范、打回阈值）
POST /api/dsh-anti-ai-fiction/audit  → body { text, dims?, specs? } → 审计报告 JSON
GET  /api/dsh-anti-ai-fiction/prompt → 去 AI 味强制指令（?dim= 按维度，?text= 针对正文定制）
```

`/prompt` 是界面「复制强制指令」按钮的数据源。这份指令**必须由后端生成**：
浏览器半自己拼的简版不知道每条雷区的 `allow`（放行条件），会把
「带身体反应就不算违规」这类豁免漏掉 —— 复制出去的指令会过度严格，
模型于是把「宿醉后阳光跟刀子一样扎眼」也当违规改掉，越改越假。

审计接口返回结构化结果（`hits` / `bySeverity` / `byDimension` / `blockCount` / `shouldReject` / `verdict` / `reworkInstructions` / `report`（Markdown））。

**`blockCount` 的语义是「不同 block 级 specId 的个数」** —— 与 `detect()` 返回的 `blockCount`、`spec.js` 的 `judgeReject` 同一口径。插件里不存在第二个含义不同的 `blockCount`。

## 文件

```
lib/
  spec.js      契约层：40 条雷区 + 40 组验收用例 + 词表 + judgeReject（单一事实源）
  detect.js    检测引擎：detect(text, options) → 命中列表（带证据与定位）
  detectors/   各维度检测器
  audit.js     审计报告生成 + 打回裁决 + 活人味替换示范
  prompt.js    强制指令 / 自查清单 / 改写指令模板
  index.js     工具注册 + HTTP 接口（本插件的 host 半）
  client.js    浏览器半
```
